# 造林合同分区接管与补植责任续接

合同、作业单元、抽查事实和管护观察来自一个虚构县域项目。面积单位为平方米，植株编号在单元内唯一，金额以整数“分”存储。所有人员、地点、资产、权利和外部流水均为本地合成，不对应真实账号；新闻中的建设进度不作为任何地块的验收结论。

使用 Python 3.11，无需安装第三方包。领域字段及协作方约定见 [资料约定](docs/contracts.md)，业务 HTTP 接口见 [API 约定](docs/api.md)。

## 组成

- `data/catalog.json`：合成合同、作业单元、抽查、缺陷、界桩更正与设施事实，以及演练身份映射（`principals` 是身份映射，不是认证凭据）。
- `partner/server.py`：外部资金协作方协议回放器（202 已收到 / 504 响应不明 / 轮询 paid、rejected），不计算任何业务资格。
- `forest/`：造林合同业务办理服务（标准库 HTTP + SQLite），覆盖分批申报、测量抽查、独立验收、局部接管、巡护缺陷合并、补植闭环、分段付款与同步结清。
- `scripts/run_checks.py`：合成数据端到端检查，日期本地推进，不等待真实季节。

## 快速开始

```sh
# 1. 启动合成资金协作方（独立状态文件）
python3 partner/server.py --port 8765 --state partner-state.sqlite3

# 2. 启动业务服务（首次启动自动建库并装载 catalog 合成资料）
python3 -m forest.server --port 8080 --db forest-state.sqlite3 \
  --fund-base-url http://127.0.0.1:8765

# 3. 一键端到端检查（自动拉起两个服务，使用临时库，结束即清理）
python3 scripts/run_checks.py
```

对已运行的服务执行检查：`python3 scripts/run_checks.py --base http://127.0.0.1:8080`。

## 运行测试

```sh
python3 -m unittest discover -s tests -v
```

包含：资料引用与协作方回放（`test_materials`）、领域纯规则（`test_rules`）、完整业务链路（`test_service_flow`，40 项断言）。

## 关键业务规则（与 docs/contracts.md 一致）

- 抽查：每单元至少两组不同日期独立抽查，第二次距栽植不少于 30 天，每组覆盖 10 株，成活率达到 90% 验收人方可签认；没有观察值不等于死亡，未抽查/争议面积不并入合格量。
- 角色隔离：施工方不能确认自己的验收；管护队不能修改施工队原记录（服务不提供原始记录改写或删除接口）。
- 接管：确认接管单元、起始时点与尚未解除的施工责任；接管不免除施工缺陷责任。观察期自实际接管起 30 日。
- 缺陷合并：同一死亡植株被多个巡护批次报告时合并为同一缺陷、只开一笔补植费；其他单元/植株的新缺陷独立建档。补植按归责区分施工整改与正常养护，费用来源、责任人、下次观察起点分别记录。
- 保留款：为单元合同款 20%，按已接收范围计额，观察期满且整改结清、显式依赖的防护设施已接收后才可释放；一个单元整改未结不影响同合同中不依赖它的单元按约付款。
- 错误地块：暂停真正受影响的付款与管护安排并发出待确认事项，原签认保留不删；已付款事实不改零，追偿/抵扣另立记录，由经办人与复核人确认。
- 付款：受理与到账分开，逐作业项回执并支持原流水查询；504 断线项继续占额度只能轮询，明确 rejected 才能重新办理，已 paid 不能再付一次。
- 同步结清：观察期到期、管护转交与付款回执在同一批次对齐实际责任；回执未结清的在途付款列入不一致清单，不会各表分别标记完成。

## 本地时钟

```sh
curl -X POST http://127.0.0.1:8080/admin/clock \
  -H 'X-Principal: project-A' -H 'Content-Type: application/json' \
  -d '{"now_iso":"2026-12-11T09:00:00+08:00"}'
```

也可在单次请求带 `X-Now` 头。`DELETE /admin/clock` 恢复真实时间。换全新 SQLite 文件即可重新开始独立演练；业务数据与协议回放数据分别保管。
